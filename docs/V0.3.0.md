# zfetch v0.3.0 — Sprint 01

## Advanced CLI and structured output

This patch introduces the first phase of v0.3.0. It preserves the existing v0.2.0
Linux ASCII logo database, custom MJ ASCII logos, JSONC schema, update manager,
and native system detectors.

## Examples

```bash
zfetch --format json
zfetch --format json --only os,kernel,cpu,memory | jq .
zfetch --only os,kernel,memory
zfetch --exclude battery,disk
zfetch --list-modules
zfetch --preset minimal
zfetch --preset full --theme nord
zfetch --theme rust
zfetch --list-themes
zfetch --hardware-details
zfetch --validate-config
zfetch --validate-config --config ~/.config/zfetch/config.jsonc
zfetch --init-config
```

Notes:

- `--format json` uses JSON output only (no ANSI, logo or decorative terminal content).
- JSON schema version is `1`, with `identity`, `system`, and `hardware` groups.
- Values from existing detectors remain strings; disk `used_bytes` and `total_bytes` are integers.
- `--only` and `--exclude` are mutually exclusive. Module names must match `--list-modules`.
- Module filters modify the configuration *before* collection, preserving lazy detection.
- `--preset minimal` turns off the logo by default, but an explicit `--logo` overrides it.
- `--preset full` enables the existing module set and displays EFI disk.
- `--theme` uses existing eight-color ANSI palettes, not RGB truecolor.
- `--hardware-details` adds CPU core/thread counts when `/proc/cpuinfo` supports them.
- `--init-config` creates a JSONC file only if it does not already exist. It will **never overwrite** a user's MJ configuration.
- `--validate-config` requires an existing configuration file; errors use stderr and nonzero exit codes.
- The existing `--update` and `--check-update` commands are unchanged.

## Scope boundaries / planned Sprint 02

CPU max clock, GPU clock/integrated classification, battery time remaining,
physical display size, deeper hardware data, responsive layout choices,
automated CI/release testing, performance comparison and updater end-to-end tests
remain on the v0.3.0 roadmap. These are **not** shipped by this Sprint 01 patch.

## Version / release status

The patch changes Cargo.toml to `0.3.0`, but do **not** publish a stable
`v0.3.0` GitHub Release yet. It is a development checkpoint pending verification
and future v0.3.0 sprint work.

## Validation on Ubuntu

```bash
cargo fmt --all && cargo check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build --profile compact
./target/compact/zfetch --version
./target/compact/zfetch --list-modules
./target/compact/zfetch --format json --only os,cpu,memory | python3 -m json.tool
./target/compact/zfetch --preset minimal
./target/compact/zfetch --hardware-details
```

Review changes and commit/push using GitHub Desktop only. Do not run `cargo deb`
or overwrite `/usr/bin/zfetch` until the complete v0.3.0 release passes QA.
