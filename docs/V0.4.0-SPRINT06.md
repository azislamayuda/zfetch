# Sprint 06 — Linux package matrix (development)

| Format | Platform | Workflow | Status |
| --- | --- | --- | --- |
| .deb | Ubuntu/Debian x86_64 + ARM64 | existing debian-packages.yml | Previously green |
| .rpm | RPM-family x86_64 + ARM64 | rpm-portable.yml | Added; CI execution and Fedora/RHEL installation tests pending |
| .tar.gz | Linux GNU x86_64 + ARM64 | rpm-portable.yml | Added; runtime cross-distro tests pending |
| .pkg.tar.zst | Arch-based x86_64 | arch-package.yml | Added; CI execution/Arch installation tests pending |

## Validation required

- Check `rpmbuild` can package native Rust binary, `rpm -qp --requires` is reasonable, and `rpm -K` works locally.
- Install RPM in disposable Fedora/Rocky environments; confirm startup, native dependencies, package count behavior, `--format json` and `--privacy`.
- Test portable tarball on compatible glibc systems; if wide compatibility is required, consider separate MUSL builds with explicit functionality tests.
- Install Arch package in a disposable Arch environment; validate `pacman -Qip`, `pacman -Ql`, and execution. Do not assume updater supports it.
- Confirm no workflows collide with Debian CI, all artifact names unique, and assembled GitHub Release checksums include every uploaded file.
- Keep Cargo 0.3.0 during development; version 0.4.0 bump and checksums at release finalization.
- No AppImage planned.

## Known constraints

- Arch PKGBUILD packages the current workspace-built binary and is NOT yet an independent reproducible AUR build recipe.
- rpm is constructed on Ubuntu and is only a candidate until runtime testing on rpm-family systems.
- Existing zfetch updater may be Debian-specific. Publishing RPM/Arch packages does not automatically make `--update` capable of installing them.
