Status: **Candidate. Do not tag or release 0.5.0 before all CI workflows pass.**

This sprint bumps `Cargo.toml` to 0.5.0 and leaves every change in the working tree.
No tag, push, or GitHub release has been made.

## Detection sources (all file reads, no subprocess)

| Item | Source |
| --- | --- |
| `.deb` install | `/var/lib/dpkg/info/zfetch.list` lists `/usr/bin/zfetch` |
| Arch install | `/var/lib/pacman/local/zfetch-<ver>/files` lists `usr/bin/zfetch` |
| RPM install | the binary is `/usr/bin/zfetch` and an rpmdb is present (ownership is assumed, not parsed) |
| Portable/source | any other binary path |
| APK | `P:` lines in `/lib/apk/db/installed` |
| Portage | `/var/db/pkg/<category>/<package>` directories |
| XBPS | `<string>installed</string>` states in `/var/db/xbps/pkgdb-*.plist` |
| Displays | `/sys/class/drm/card*-*/{status,enabled,edid}`, EDID preferred timing |

XBPS note: counting `*.plist` files would include `pkgdb-*.plist` itself and miss packages
that have no files list, so the installed state inside pkgdb is counted instead.

## Manual test steps after GitHub Desktop commit to main / push origin

1. Run all four packaging workflows (Debian, RPM and portable, musl, Arch).
2. On GNOME: compare `zfetch --only display` with the 0.4.0 output (see open questions).
3. On Hyprland or Sway, if available, check the `WM` line.
4. On a `.deb` install: `zfetch --check-update` should show `Installed via : .deb (dpkg)`.
5. On Alpine, Gentoo, and Void containers: `zfetch --only packages`.
6. Paste `zfetch --doctor --privacy` from a test machine and confirm that no
   username or hostname appears.

## Open questions for the owner

- Display output without D-Bus on multi-monitor setups and on changed resolutions or
  refresh rates. EDID shows the preferred mode, and connector names follow the kernel (`HDMI-A-1`).
- The `.deb` workflow produces per-arch `SHA256SUMS-<arch>` files, but `--update` needs one combined
  `SHA256SUMS` release asset. The v0.4.0 release has one (checked with `gh release view`), so attach
  a combined `SHA256SUMS` covering all nine packages to v0.5.0 as well.
