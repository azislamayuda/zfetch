# zfetch v0.2.0 — Smart Logo & Safe Update (development candidate)

This source overlay extends the existing **zfetch 0.1.0** project. It does not replace the Linux hardware detection modules.

## New features

### Automatic distro ASCII logos

Run `zfetch` with no explicit logo to select an embedded text logo from `/etc/os-release` (`ID` first, then `ID_LIKE`; `/usr/lib/os-release` as fallback). The initial database is in `assets/logos/*.txt`. This file database is compiled into the binary via Rust `include_str!` for fast startup.

Supported IDs: Ubuntu, Debian, Linux Mint, Pop!_OS, Zorin OS, elementary OS, Kubuntu, Fedora, Arch, Manjaro, openSUSE, plus a generic Linux fallback.

**Priority / backward compatibility:**

1. `--no-logo` hides logos.
2. `--logo /path/logo.txt` takes priority over everything else.
3. Existing `logo.source` in `~/.config/zfetch/config.jsonc` takes priority.
4. Existing `ZFETCH_LOGO` environment variable or `~/.config/zfetch/logo.txt` takes priority.
5. Otherwise the distribution logo is selected automatically.

If you currently use `~/.config/zfetch/MJfont.txt`, it stays intact. To **test distro auto-logo** without losing MJ, create a separate config:

```bash
cat > /tmp/zfetch-auto-logo.jsonc <<'JSON'
{
  "logo": {"enabled": true},
  "modules": {
    "system": ["os", "kernel", "arch"],
    "hardware": ["cpu", "memory"]
  }
}
JSON
./target/compact/zfetch --config /tmp/zfetch-auto-logo.jsonc
```

### Explicit-only update checker

```bash
zfetch --check-update
zfetch --update
```

- Queries `https://api.github.com/repos/azislamayuda/zfetch/releases/latest` only for an explicitly requested update command.
- Compares three-part stable version numbers.
- `--check-update`: shows the installed/latest versions, downloads nothing.
- `--update`: offers an update only when newer stable version is available.
- Auto-install is supported **only for dpkg-managed x86_64 installs** with a matching `.deb` GitHub Release asset and published `SHA256SUMS` asset.
- Asks for confirmation before any download, then checks artifact size, SHA-256 checksum, Debian package name/version/architecture, and installs via `sudo apt-get install`.
- Missing checksum? Wrong architecture? Missing release asset? Refuse auto-install and leave installed binary untouched.
- Updater requires installed `curl`, `sha256sum`, `dpkg-deb`, `sudo`, `apt-get`. Debian package metadata includes apt/curl/coreutils/dpkg as dependencies; sudo access depends on the user's system.
- Updating is not completely risk-free: checksum verifies transfer integrity against the same GitHub release, but is not a separate publisher signature. Only install releases you trust.
- Regular `zfetch` never checks GitHub and has no network overhead.

**Important:** Testing a self-update requires a newer signed-off GitHub Release than the version currently installed. In v0.2.0 development, test version comparison and the no-update path. Do not attempt to install v0.2.0 automatically from v0.2.0; first package and deploy v0.2.0 using `cargo deb` and APT.

## Local validation in Ubuntu

```bash
cd ~/ZDATA/ME/GITHUB/zfetch
cargo fmt --all
cargo check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build --profile compact
./target/compact/zfetch --version
./target/compact/zfetch --help
./target/compact/zfetch --config /tmp/zfetch-auto-logo.jsonc
./target/compact/zfetch --check-update
```

If all tests pass, **commit/push using GitHub Desktop**, not Git commands.

Suggested GitHub Desktop commit summary:

```text
feat: add automatic distro logos and safe GitHub update manager
```

## Debian package and release

```bash
cargo deb
dpkg-deb -f target/debian/zfetch_0.2.0-1_amd64.deb Package Version Architecture Depends
sudo apt-get -s install ./target/debian/zfetch_0.2.0-1_amd64.deb
```

After reviewing the simulation, install using APT. To enable future updates, attach **both** the `.deb` and a SHA256SUMS file to the GitHub Release:

```bash
cd target/debian
sha256sum zfetch_0.2.0-1_amd64.deb > SHA256SUMS
```

This is a **source development candidate**, not a compiled or tested binary. Run Cargo checks on Ubuntu before committing or publishing the release. Do not remove existing v0.1.0 package until v0.2.0 has passed full testing.
